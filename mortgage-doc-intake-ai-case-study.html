The problem

Every mortgage application needs a specific set of documents before it can move to underwriting, and exactly which documents are required depends on the loan type (conventional vs. FHA) and the borrower's employment situation (W-2 vs. self-employed). Manually tracking which file is missing what, whether a bank statement is still within its freshness window, and whether every document actually matches the borrower's name is repetitive, easy to get wrong, and a common source of delay in the loan process.

How it works

The system builds the exact required-document checklist for each file, then checks what's actually been submitted against it — and routes the result down one of three genuinely different paths, not a single generic "flagged" bucket.

Deliberate design decisions

A missing document and a suspicious one are not the same problem

A missing document is a mechanical gap — the system knows exactly what's needed and can draft the request itself with no ambiguity. An illegible scan, a stale statement, or a name mismatch all require a person to actually look at the document and use judgment. Collapsing these into one "incomplete" bucket would have meant either annoying a human with routine missing-paperwork requests, or letting a real problem slip through as a false "complete."

The checklist logic isn't exposed as a casual config

Which documents a loan needs is largely dictated by investor and agency guidelines, not personal preference — so the checklist rules live in code, versioned and reviewable, rather than as a setting someone could accidentally misconfigure.

Freshness has a real, stated threshold — not a vague "recent enough"

Bank statements older than 60 days are explicitly flagged, with the exact age reported in the Slack alert. A specific, visible number is something a processor can act on immediately; "this looks a bit old" is not.
